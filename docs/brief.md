# Three Atlas：首个作品接入

## 本次目标

建立可运行的作品总览，将 WHERE STARS REST 作为第一个可点击、可独立打开的 3D 作品。先准备内容与结构，首页视觉只是可替换的初稿，完整视觉方向交给后续 Opus 5.5 设计。

## 已确定的约束

- 项目与网站统一叫 **Three Atlas**，仓库为 `three-atlas`，中文名为「三维图鉴」。
- 首页通过卡片汇总作品，卡片进入各自的独立网页。作品可直接访问、刷新和分享。
- 首作沿用作者最后命名的 **WHERE STARS REST**，保留已有树光、粒子、云层、交互和音效。
- 原始作品保留在原项目，本仓库使用独立源码副本，不依赖相邻目录运行。
- 首页、卡片内容、作品代码分别维护；已有相同需求才提取共享代码。
- 首页只加载图片与轻量界面，不为每张卡片启动 WebGL。
- 网站简单、简约、大气，作品画面优先；默认不使用绿色装饰。
- 支持中英文内容、键盘导航、手机视口、减少动态效果；不给只有一个作品的网站增加空分类或虚构作品。
- 保留 Three.js `0.186.1`、Vite `8.3.5` 与原有依赖许可证。
- 内容准备阶段完成本地运行验证与交接文档；随后按用户要求同步到私有 GitHub 仓库。不添加项目许可证或配置线上部署。

## 实现选择

采用 Vite 多页面静态站点：`index.html` 为画廊，`experiences/<id>/index.html` 为独立作品。作品目录由 `content/works.json` 登记并自动成为构建入口；相对资源路径兼容根路径与 GitHub Pages 项目子路径。

首页使用原生 JavaScript 和独立 CSS，便于后续替换视觉。没有引入 React、SPA 路由或场景插件接口：当前只有一个已有原生作品，多页面结构足够处理进入、返回和隔离 CSS/WebGL 生命周期。

参考 Awesome AI Motion 的「封面卡片 → 内容」浏览方式，以及 Tripo Studio 的作品画廊；不复制它们的品牌、媒体、字体或生成工作台。

## 完成条件

1. 首页显示 WHERE STARS REST 的真实封面、简介与入口。
2. 点击卡片可进入原有实时 3D 作品，拖动、缩放、亮度、暂停与复位可用，并可返回图鉴。
3. 独立作品的深链接刷新可用，根目录和 `/three-atlas/` 子路径均可运行。
4. 搜索、中英文切换和空结果状态可用；首页不加载 Three.js。
5. 原有场景测试、内容完整性检查、生产构建与相关浏览器验收通过。
6. 为下一位设计者写清稳定的数据与路由约定、可自由改动的视觉层，以及未验收范围。
